# 异步任务排队超时

异步视频任务不再无限排队。入队时按当前 `generation.video_timeout` 固化排队截止时间，默认 1500 秒（25 分钟），取值沿用 60–7200 秒范围。管理后台已有的视频超时设置会影响之后入队的任务；已入队任务的截止时间不会因重试、配置变更或服务重启而延长。

## 对外行为

- 新提交和查询响应增加 `queue_expires_at`（UTC Unix 秒），表示排队截止时间，不是生成结果文件的过期时间。
- 超时且尚未开始向上游提交的任务变为 `failed`，`progress=100`，错误代码为 `QUEUE_TIMEOUT`，提示“任务排队超时，已自动结束，不会继续生成。”
- 超时任务退出活动排队池，释放容量，不再返回 `queue_position`；失败记录保留供查询，不删除任务 ID。
- 领取任务、准备素材、刷新账号不代表已开始向上游提交；这些阶段仍受排队截止时间限制。
- 原子提交校验通过后，状态为 `processing`，按原有生成超时继续处理。已开始提交或已取得上游任务 ID 的任务不受排队清理影响，不会因为结果晚到而再次提交。
- 同步请求、图片异步任务及已经进入正常任务表的任务不受这个视频排队规则影响。

## 实现与防护

1. `async_task_queue.expires_at` 保存不可重置的排队截止时间。升级时老任务从原始 `created_at` 加已配置的视频超时推导截止时间，不从部署时间重新计时。
2. 独立清理协程每约 2 秒扫描整个等待池；即使提交线程忙于账号校验，队尾过期任务也能结束。入队、领取、查询和重试更新同时提供补充清理。
3. 数据库清理与 `admit_async_task_submission()` 使用 SQLite 写事务互斥。FlowClient 在实际视频提交入口调用任务专属校验，已经失败或过期的旧领取记录不能继续生成。
4. 终态记录不能被旧线程的错误恢复改回 queued；清除其序列化媒体提交载荷，保留失败原因和历史信息。
5. `submission_started_at` 区分已经进入上游提交的任务。服务重启后若该记录没有上游 ID，按“提交结果未能确认”终止自动重试，避免重复扣费；有上游 ID 时继续原任务挂接/结果处理。
6. 排队到期不是账号故障，不增加账号连续错误计数、不触发验证码自愈或重登录。

## 验证边界

自动化测试覆盖全池清理、满池容量释放、无账号等待、领取后过期、账号刷新期间过期、生成准备期间过期、最终提交拦截、并发隔离与竞争、重试不续期、迁移/重启、已提交任务保护及公开错误格式。所有测试使用临时数据库与模拟上游，不消耗积分。

这项改动只结束过期排队任务，不会修复账号登录态或解除代理风控。部署前应确认没有结果尚未确认的旧版提交线程，再按现有部署保护流程更新；不要直接清空生产队列或强制重启。
