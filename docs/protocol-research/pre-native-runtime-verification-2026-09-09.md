## 重启回归与退出缺陷

首次停止登录辅助程序的检查仍在运行时，部署已经开始；未获得辅助进程退出完成的确认。检查进程随后随容器替换退出（137）。这一执行顺序没有形成可靠的正常退出证据，不能把该次失败直接归因为代理、账号或设备绑定。

代码同时存在可独立确认的退出缺陷：`NativeCdpAccountBrowser.stop()` 在发送 `Browser.close` 后立即执行 `process.terminate()`，没有等待 Chromium 异步退出、完成会话落盘。

本地修复：先等待自然退出 8 秒；超时才 terminate 并等待 5 秒；仍未退出才 kill 并等待 3 秒。使用有界 `Popen.wait(timeout=...)`，避免 asyncio 超时后留下无界等待线程。增加了自然退出、terminate 超时升级、kill 升级三个测试。

重启后的只读检查还观察到：

- `Default/Preferences` 报告 `profile.exit_type = Crashed`。
- `.google.com` 根域登录 Cookie 缺失，Flow OSID 和 Labs ST 仍存在；`.google.co.th` Cookie 仍存在。
- 已保存 Cookie 的加密前缀为 `v10`。这一观察本身既不能证明解密失败，也不能证明设备绑定是唯一原因。

需要在完整的正常退出/重启条件下再次核验持久化；当前尚无这项成功证据。

## 防止再次中断登录

诊断部署辅助程序已增加前置检查：只要目标登录辅助程序、隔离测试 API 或其浏览器仍存活，即拒绝容器重建，不再只检查任务 inflight/processing 数量。已实际验证该检查拒绝部署，容器未发生再次替换。

下一步顺序：

1. 用户在目标桌面重新登录；避免采集密码、MFA 或登录网络凭据。
2. 验证同一 worker 的新站 RPC，必要时完成同一浏览器 Labs 官方登录流程；再验证真实余额。将目标自身的凭据更新到隔离数据库，不复制源会话。
3. 在同一浏览器进程内通过隔离 API 提交一次基础图片请求，验收终态与完整图片文件；再提交一次 `abra_r2v_4s_360p` 视频，核验终态、下载、尺寸、时长、真实余额变化。请求日志在发送前落盘；未知结果只查询，不自动重提。
4. 成功后再进行有退出完成证据的同 Profile 重启回归，之后才更新生产镜像、恢复账号调度。不得在登录/测试进程存活时强行部署。
5. 恢复历史已出片任务需经过现有水印/缓存后处理，不能仅把数据库状态改为成功。
