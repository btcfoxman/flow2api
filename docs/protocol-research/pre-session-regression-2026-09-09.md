# 2026-09-09 pre 会话链修复与验证

本记录取代“旧页面 HTTP 200 即说明旧生成链仍可用”的初步判断。

更新：用户重新登录后的单账号隔离实测见 [重新登录验证](pre-relogin-verification-2026-09-09.md)。已确认旧任务有视频产物；同公网 IP 下完整 Cookie 迁移仍返回 401，并伴随源站会话失效。本文下方“尚未完成”是上一轮状态，以新记录为准。

## 真实问题

- 部署 74f1f1f 后，08:55–09:40 +08 的 28 条视频提交全部失败：23 条被包装为上传失败、5 条获取 reCAPTCHA 失败。这批不是上游 429。
- 23 条底层上传错误均发生在页面准备阶段，尚未向图片上传接口发起请求。
- 浏览器实测：Labs 项目 URL 首先 HTTP 200，但脚本随后跳转 `flow.google.com/project/...`；没有有效新域会话时最终为 `/about`。因此不能只修改回旧域名。
- 抽查 5 个有 google_cookies 的失败账号，快照只有 accounts/flow/www 子域 Cookie，全部缺失 `.google.com` 登录 Cookie。
- 插件 1.2.1 缺少 `https://google.com/*` host permission。Chrome cookies API 只返回拥有对应域权限的 Cookie；子域权限不能代替主域权限。参见 [Chrome 官方 cookies 文档](https://developer.chrome.com/docs/extensions/reference/api/cookies)。现有快照缺失与该权限缺口吻合，尚未在当前源浏览器完成修复前后采集对照。
- 同步端和服务端此前仅用 OSID 判断会话字段齐全，因此不完整快照也会报告同步成功。Cookie 保存成功不能证明新域认证通过，更不能排除设备绑定等后续限制。
- 上传错误排除计数的规则收到的是中文公开文案，而非原始分类，导致规则失效；8 个账号恰好连续失败 3 次并停用。

## 修复边界

1. Labs 与 Angular 页面缓存按协议隔离；未开启 RPC 时仍使用 REST 提交，不因有 Cookie 而切换视频上传协议。
2. 页面等待 complete 并重新检查正确 origin/path；新域总是检查认证 bootstrap，不能用 Cookie 字段存在代替登录验收。
3. 若浏览器确认旧站迁移到新域，只在提交之前切换到经过认证的新域页面；不重复生成、不在已提交后回退或切账号。
4. 原生浏览器仍与源同步服务分离，使用账号绑定代理。旧链路不会为了准备 Labs 页面而反复导入 Google 快照。
5. 新增 NativeSessionError 分类；公开端友好 503，后台保留脱敏 stage/reason，生产关键事件不再依赖 debug 开关。先分类再转换公开文案，不将本地会话错误累计为账号故障。
6. 插件 1.2.2 加入 Google 主域权限和采集；插件、tupdater、后端均检查主域 SID/PSID 与 Flow OSID，后端拒绝不完整新快照，不覆盖旧配置。旧 ST-only 请求仍兼容。

7. HTTP 401 保留鉴权分类，不自动换提交协议/账号；查询接口不再使用同一失效 AT 重试另一请求结构。
8. 已受理任务轮询逐次读取同账号的新 AT/ST；遇到会话问题，在原有轮询时间预算内等待同步，不再三次即终止。超过预算仍按“查询失败”收口，保留原 operations，公开提示结果未确认、勿重复提交，不累计账号故障。注意：此时任务表仍是 failed，并非已实现长期挂起/重启自动恢复；不能把它解读成上游生成失败。

- 由于目标探针与线上执行有并行，无法将源会话失效归因于单一机制；完整 Cookie 不保证跨 Profile 可用，也不能据此断言设备绑定就是唯一原因。下一轮先隔离测试账号，只保留一个目标 Native Profile。
- 无有效鉴权读取事后余额，无法确认本轮测试扣费；线上已受理任务亦可能消耗额度。不能宣称“零扣费”或“已成功出片”。
