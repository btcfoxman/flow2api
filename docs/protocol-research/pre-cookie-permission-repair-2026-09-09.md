# 3.5 pre：插件 Cookie 缺项修复与生产验收

本记录补充此前恢复记录，不能把旧版本的个别成功当作所有同步账号均已恢复。
时间统一以 UTC 记录；服务器日志中的本地时间为 UTC+8。

## 已证实的故障链

账号 52 的源浏览器已登录，但旧插件只有 HTTPS 主机权限。实际 Chrome
`cookies.getAll` 返回中缺少 `.google.com` 的 `SID`、`HSID`、`APISID`、
`SIDCC`。旧完整性检查接受 `__Secure-1PSID` / `__Secure-3PSID`，因此
出现“插件同步成功、OAuth 有效，但目标 Flow 页面落到 `/about`”的假恢复。
这不是把其代理切换为全局代理可以解决的问题。

在相同扩展 ID、相同浏览器 Profile、相同缓存配置下补齐精确 Google 主机的
HTTP Cookie 读取权限并重新加载后，Chrome API 确实返回上述四项；同步到
目标独立 NativeCDP Profile 后，同一账号的两条原队列视频完成。
HTTP 主机权限用于 Cookie API；同步和 Flow 网络请求仍为 HTTPS。

Chrome 官方说明 Cookie API 同时要求 `cookies` 和对应主机权限：
[chrome.cookies 权限说明](https://developer.chrome.com/docs/extensions/reference/api/cookies)。
具体缺失四项及修复后的变化来自本次真实 Chrome 对照，不仅是文档推断。

## 修复范围

- 插件 1.2.4：补齐精确主机权限；发送前检查权限和根 SID；同步超时覆盖服务端
  登录预检；区分“保存成功”和 `native_session_verified=true`；保留原扩展 ID
  及缓存的代理、地址和连接 Token；本地构建不发布私有默认配置。
- Flow2API `8f5a84a`：不再以 Secure PSID 替代根 SID；保存同步数据后，在
  目标账号原代理、独立 Profile 和准确项目页进行不收费的登录预检；未通过
  不自动启用原禁用账号；确认登出的外部快照不再每五分钟用用户任务反复试错。
  新凭据或成功预检可解除该账号隔离；独立本地登录仍保留恢复路径。
- Flow2API `9177c51`：冷启动时空 Cookie 快照同样被排除；准确项目 URL 和
  有效 Angular bootstrap 可证明页面就绪，不因非必要资源的加载超时误判；
  `/about` 仍拒绝；Docker 构建排除测试日志和运行时目录，避免测试事件混入生产。
- tupdater `fca7069`：采用同样的根会话完整性判定；收到目标预检失败后不再
  报告可生成，不清空源凭据、不自动重登。源服务运行实例另行核验，不能只凭
  镜像构建成功就声称那一端已更新。
- Flow2API `83027da`：下载失败后的 wget/curl 改为异步子进程，取消或超时会
  终止并回收子进程；命令行下载先写独立临时文件，成功后原子发布，不缓存半截
  文件或 HTTP 错误页；SOCKS 不再交给不支持它的 wget，保留该任务代理绑定，
  不继承环境中的其他代理。非流式轮询也记录状态，增加视频后处理阶段。
- Flow2API `b6daa70`：实测日志中的 `PUBLIC_ERROR_SEXUAL` 明确归为内容策略
  拒绝，返回友好的 400，不自动重试、不惩罚账号；没有尝试绕过内容限制。
- Flow2API `fdee602`、tupdater `5b58e40`：零积分账号的已认证余额响应可能省略
  `credits`。账号 37、38 的同出口只读实测均返回 HTTP 200 及
  `serviceTier=SERVICE_TIER_INTERMEDIATE`、`sku=G1_TIER1`、
  `userPaygateTier=PAYGATE_TIER_ONE`，却因缺少零值字段被旧同步校验误报 503。
  仅这种完整、无错误的账户层级响应补零；空对象、401/403/429、显式异常余额
  仍拒绝。零积分证明认证有效，但不会因此获得生成资格。

回归结果：Flow2API 381 项，tupdater 123 项，插件 Node 测试 17 项通过。
源浏览器与目标服务器 Profile 始终分离，未覆盖账号 43 的独立服务器登录。
