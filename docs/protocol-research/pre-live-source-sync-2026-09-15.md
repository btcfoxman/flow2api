## 已排除与未确定

- 源浏览器关闭、服务重启不是本轮失败的必要条件；持续运行不能单独修复。
- 源检测失败不是只读取旧数据库布尔值所得，刷新页面也复现未登录。
- 目标的成功来自真实额度/项目 RPC 预检，不只是管理界面缓存。
- 源与目标根 SID / PSID / OSID 的密文字节相同，SIDTS / SIDCC 分化。不同密文字节不独立证明明文不同；更不能仅据先后关系断言目标撤销源会话。
- 没有证据支持把当前根因直接命名为 Google 的固定 TTL、设备绑定或特定风控算法。

## 代码链路与后续边界

`TokenManager.sync_flow_session` → `BrowserCaptchaService.verify_flow_import` → 临时 `sync-check-*` Profile → `_flow_account_snapshot_locked` → 将网络请求后的 Cookie 写入目标账号 → 正式目标 Profile 再次验证。

这意味着源、临时验证环境和正式目标会涉及同一组会话材料，不是各端分别完成的独立授权。临时验证环境返回的旋转 Cookie 是后续对照重点，但当前观察尚不能将它确定为失效根因。

暂不修改生产认证策略：保留导入前身份校验、失败后的人工登录要求、源与目标分离及代理一致性约束；不能用取消校验、回灌目标 Cookie、伪造过期时间或高频重试掩盖失败。

若要验证独立授权是否消除相互影响，需先取得用户对 g1 源/目标分别登录、停止复制该组会话的明确选择；不能将它当作用户已授权的架构变更。
